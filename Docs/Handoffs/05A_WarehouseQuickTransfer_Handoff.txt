三、实际API与职责

WarehouseUIController：
public Func<string, bool> QuickTransferRequested { get; set; }
public bool TryQuickTransfer(string instanceId)
返回本次请求实际成功与否。06绑定回调并调用真实Coordinator、给出双语结果；05不引用06类型，不自行改Owner/ContainerId、不添加背包摆放、不扣EV。没有回调或本地资格不符即false；false不是让ItemView退回普通拖拽的指令，快捷手势无论成功失败都必须消费。
当前已读实现先验证CanInteract，再拒绝quickTransferInProgress、当前拖拽/遗弃确认、HasPendingInteraction，以及CanBeginDrag回调报告的外部忙状态；校验TryGetStoredItem后才调用委托。没有委托反馈warehouse.result.not_ready，交互冲突反馈warehouse.result.busy，物品失败用现有ResultKey。用本地同步bool保护回调期间重入，finally恢复，不提前Claim仓库占用；06在完整提交内申请/释放占用，避免找位前就被自己的占用拒绝。返回委托的真实bool，不把处理过请求等同于业务成功。
当前ItemView在左键PointerDown锁定左右Ctrl状态，PointerClick先清状态并Use再请求；false没有普通选择/拖拽回退。Ctrl手势跨过拖拽阈值时消费且不请求，不进入普通拖拽；普通手势已开始拖拽后Ctrl不转换。普通拖拽保留pressPosition和pressEventCamera，避免越过阈值后错用目标作抓取原点。Bind（包含Controller同源重绑）、Close、LayoutChanged、ContextChanged、取消、失焦/暂停、停用会清本地手势，ItemView换绑/停用也清自身手势与旧drag token。以上已做静态阅读，尚未经Unity编译或输入回归。

WarehouseManager：
public WarehouseResult TryFindSpaceForExternal(string instanceId, bool preferredRotated, out Vector2Int cell, out bool rotated)
已读Manager落盘实现：先检查IsReady→IsManagementAllowed→busy/HasPendingInteraction，再复用GetPlacementCandidate和原grid.CanPlace校验，不提前Claim。先固定preferredRotated，按y由小到大、同一行x由小到大查找；该方向所有位置均失败且canRotate允许、宽高不相同时才试另一方向。不以每格轮换方向破坏当前方向优先，不重排已有物品。
Success输出合法左上角与最终方向。所有失败cell=(-1,-1)、rotated=preferredRotated：未准备NotReady，非庇护所NotInShelter，占用/通知中Busy，无实例NotFound，终止归属WrongOwner，Storage属于其他containerId为WrongContainer，已存在实例DuplicateInstance，非法定义InvalidConfiguration，首选旋转但定义禁止旋转为RotationNotAllowed。至少一种方向尺寸可放但无空矩形时Overlap；所有允许尝试方向均尺寸不符时OutOfBounds。不可旋转物不会退到另一个方向；方形物无需重复搜索。此为源码语义，运行结果仍待07。
查询不得修改Owner、ContainerId、IsRetained、UseRound/UsesThisRound、任何Placement、升级尺寸、EV、占用或通知；快捷提交仍需06用返回坐标调用Coordinator并重新校验，查询结果不是保留空位或提交凭证。满仓保持源物原坐标，不丢弃或强行塞入。
