四、数据职责和操作顺序

01保存ItemInstance身份、归属、ContainerId、UsesThisRound、UseRound、IsRetained及找回记录。04的BackpackPlacement仅引用同一实例并保存X、Y、Rotated；不复制次数、HP或EV。
BackpackGrid是本模块自己的List和矩形检查，不继承仓库算法、不使用UI Transform判断占格。原点为左上角(0,0)，x向右、y向下；旋转90度交换定义宽高，不修改ItemDataSO。
BackpackPlacement属性只读，GetPlacements返回只读快照。后续移动不会改写旧快照坐标；快照的Item仍是01的权威对象，查询Owner等属性反映其最新状态。

拖拽开始保存原Placement和当前编号token。原占格始终保留；预览校验只忽略自己的旧矩形，其他物品正常参与碰撞检查。ItemView以鼠标按下位置计算抓取偏移，避免快速拖动跨过UGUI阈值后把目标当成起点。
松手再次检查当前token、开包状态、同一实例、实际Owner/ContainerId、原摆放未被其他操作改变及目标合法，然后TryMove再次校验并提交一条记录。非法松手不执行移除、丢弃或重建实例。
CancelDrag清除有效token和预览，有拖拽时通知DragCancelled。Close先把IsOpen设为false，并在原先打开时通知Closing让来源会话先清理，再CancelDrag、隐藏View、SetBackpackOpen(false)；closing标记防止递归关闭。旧OnEndDrag携带已失效token不能提交，也不能影响下一次预览。关闭按钮、Tab、有效伤害、死亡、控制器停用、换绑玩家、失焦/暂停共用这条清理路径。
死亡只清背包打开标记；02的死亡限制继续有效。04不RecordLoss、不扣EV、不清携带物。实际死亡损失由08协调，06/08完成归属变化后通过明确接口清理指定布局。

包内移动和使用前确认真实实例、Owner==Backpack、稳定containerId（默认player-backpack）以及合法摆放；仅有Backpack归属不足以使用。
右键唯一业务入口是BackpackUIController的Player/UseItem克隆动作，按实际最上层EventSystem射线命中的本包ItemView查询目标。ItemView的OnPointerClick只处理左键，不调用使用。
BackpackManager.TryUseItem把真实PlayerHealth传给01.TryUseItem。成功且Owner==Consumed时先移除该实例布局再发Changed；保留的医疗包不移除；失败不改变布局。busy覆盖使用、移动及通知期间重入，监听者读取已经一致的状态。
医疗包每轮一次、回满、使用后保留，食物成功回复1HP后消耗，满血不扣次不消耗，都沿用01。04不开新轮次、不ResetForExploration、不修改IsRetained。

五、06、08、09可直接接入的入口

常驻与查询：
- static BackpackManager Resolve()：只解析有效GameBootstrap.Instance下启用的管理器，不创建新根。
- bool Initialize(ItemManager source)：首次初始化布局；重复同来源保留数据，不接受换另一份Items冒充重新绑定。
- int Width、Height；string ContainerId；bool IsReady；ItemManager Items。
- IReadOnlyList<BackpackPlacement> GetPlacements()。
- bool TryGetPlacement(string instanceId, out BackpackPlacement placement)。
- BackpackResult TryGetCarriedItem(string instanceId, out ItemInstance item)。

包内操作：
- BackpackResult CanMove(string instanceId, int x, int y, bool rotated)：纯查询。
- BackpackResult TryMove(string instanceId, int x, int y, bool rotated)：成功提交后通知。
- BackpackResult TryUseItem(string instanceId, PlayerHealth target, out ItemUseResult useResult)：先看BackpackResult，再看ItemUseResult；前者Success不等于治疗成功。

给06的局部协调能力：
- BackpackResult CanPlaceExternal(string instanceId, int x, int y, bool rotated)。
- BackpackResult TryAddPlacement(string instanceId, int x, int y, bool rotated)。
- BackpackResult TryRemovePlacement(string instanceId, out BackpackPlacement removed)。
- BackpackResult TryRestorePlacement(BackpackPlacement placement)。
- void NotifyChanged()；event Action Changed。

外部检查/新增接受现存World、Container、Storage实例，或属于本containerId的Backpack实例；拒绝重复加入和Consumed/Lost/PendingRecovery等终止/待恢复状态。新增和恢复不会修改01归属，移除允许物品归属已转移/记损后清理原布局。
TryAddPlacement、TryRemovePlacement和TryRestorePlacement都是静默布局操作。06应先校验来源和目标，再同步协调两边布局与01.TrySetOwner，失败按原Placement和来源状态恢复；全体一致后才NotifyChanged。04不提供通用事务或所有权转移许可，也不反向依赖06。
恢复同样经过当前边界/冲突检查，不覆盖他人物品，不凭一个旧Placement复活已消耗或已损失实例。

UI与场景入口：
- ResolveBindings()解析存活常驻模块；BindPlayer(PlayerController)先关闭和清理旧玩家，再解除旧订阅并绑定新玩家。
- SetShelterContext(bool)由08/09明确指定。探索要求有效已准备玩家；庇护所可允许未准备/无场景玩家整理，但死亡玩家仍不可开包，无有效存活且已准备的PlayerHealth不能治疗。
- TryOpen()、Close()、CancelDrag()；BeginExternalPreview(string instanceId)提供外部预览/取消边界。
- BeginItemDrag/UpdateDrag/EndDrag的token回调由BackpackItemView使用，不由09再实现另一套拖拽提交。

06已补入的实际同步接入点：
- Func<bool> CanBeginDrag：来源会话可阻止选择、开始拖拽与使用，未赋值时沿用04自身检查。
- Action<int, Vector2, Camera> DragUpdated：在04完成本次预览更新后，将有效token和指针位置交给已绑定的协调者更新目标显示。
- Func<int, Vector2, Camera, bool> ExternalDropRequested：EndDrag在token仍有效时调用唯一同步处理者；返回true表示该请求已处理，04保留反馈并取消临时预览；未接回调或返回false时继续04原有路径。外部预览无法由04本身提交真实转移。
- event Action Closing：IsOpen清为false后、取消和解除玩家限制之前清理来源会话；监听者不要反向调用Close。
- event Action DragCancelled：存在的拖拽已清理后通知协调者，不承担第二次物品业务。
- int DragToken、Vector2Int DragGrabOffset、bool IsDragValid(int token)、void CancelDrag(int token)、public SetFeedback(string key)：为同步协调提供当前资格、抓取格、精确取消和本地化反馈。
BackpackItemView.OnDisable会携带自己的token请求取消；BackpackView.TryScreenToCell同时要求面板启用且目标是实际最上层本窗口，避免穿过来源面板或确认框放入。06的回调绑定/释放与真实转移联验由06执行，本次04两尺寸复验覆盖未绑定回调时的原有行为。

布局常驻在现有GameBootstrap下；UI、Player和EventSystem属于场景。场景重载后重新绑定存活入口，不补发物品、不清布局、不刷新医疗包次数。08负责成功撤离、死亡结算和下一轮准备，09复用唯一Tab/R/右键监听，F10仍归03。
