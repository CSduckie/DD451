IHealthTarget精确签名：int CurrentHealth { get; }；int MaxHealth { get; }；void Heal(int amount)。治疗必须同步、封顶、不复活，不能由事件异常中断完成；02提供真实HP。ItemEffectSO只声明abstract void Execute(IHealthTarget target)。
定义、目录与HealEffectSO均有bool TryValidate(out string error)；目录有ItemDataSO FindDefinition(string definitionId)。实例公开读取身份、定义、归属、来源/容器、保有、次数与轮次、原点、找回资格、最近损失原因和地图许可状态，修改统一通过ItemManager。

字典用于“按ID直接找到同一件物品”，不是另一个服务系统；集合查询返回副本防止外部删除登记。SO定义与实例分开，所以用掉foodA不会影响foodB或Food.asset。
唯一登记跨World/Container/Backpack/Storage一致；PendingRecovery仍保留唯一索引。查询只返回原实例；首次或找回地图出现还需TryClaimUniqueSpawn的单次许可。OriginalSpawnPointId使用“地图/点位”稳定字符串，不保存Transform。06先解析原地图点位和Prefab，确认可创建再领取；同轮不找回，下轮用同一InstanceId且不再抽掉落概率。
临时落地只改归属，不立即登记丢失。06/08确认三种真实损失后才RecordLoss；普通物品Lost不会恢复。TrySetOwner拒绝从PendingRecovery/Consumed/Lost直接移回背包。
医疗包成功不改变身份、归属或保有；食物成功只消耗该实例。多个有效治疗按列表执行，前项回满后后项跳过，整次只计一次。空/未知/无效效果先统一拒绝；满血、非背包或失效目标不扣次。使用期间写操作被阻止，避免生命回调重入重复消费；本轮额度只由更大的BeginRound刷新。
没有UI事件驱动第二次业务。04/06将真实布局校验、01使用与成功后的布局移除放入同一同步完整操作，最终一致后通知显示。当前不存在真实容器，尚未验证这一集成保证。
