黑夜默认环境与画面发灰：只读工程审计
日期：2026-10-19
审计范围：E:/DD451；磁盘中的 Assets/Scenes、实际相机 Prefab、URP 资产、Volume、环境材质与 Editor 场景搭建脚本。
边界：未调用 Unity、未读取 Editor 当前运行状态、未改 Assets/ProjectSettings。以下是保存到磁盘的配置证据，不是当前 Game 画面实测，也不证明发灰的最终根因。

结论
1. Assets/Scenes 共 12 个场景，只有 Shelter 已绑定 ShelterNightSkybox；其余 11 个仍绑定 Unity 内置默认天空盒。统一黑夜目前尚未完成。
2. 正式 Shelter/Ruins 继承 PlayerCamera：ClearFlags=Skybox，后处理关闭。全部 12 个场景 Fog=0。现有证据不能把正式游戏画面发灰归因于 Bloom、色调映射或雾。
3. 工程没有现成的新场景黑夜初始化脚本或项目 Scene Template。只更改当前场景不会覆盖之后新建的场景；部分旧 Builder 还明确创建 SolidColor 相机。
4. 建议先统一场景天空盒和必要的世界相机 ClearFlags，再由唯一 Editor 操作者用同机位 Game 帧确认灰感是否仍存在。不要为了“去灰”先整体改 Gamma/Linear、HDR、后处理开关或相机跟随。

四、发灰原因候选，按证据区分
A. 已证实的不统一：Ruins 和绝大部分场景仍是内置默认天空盒，且环境照明/反射来自 Skybox。这会保留日间背景/照明来源，与黑夜目标不一致；是否就是用户说的灰感，尚未实测。
B. 候选：背景地平线的程序天空颜色，或默认天空照明/反射对低饱和材质的影响；白色直射光在 Ruins 强度1.2。应通过固定机位先仅替换夜空，再对照环境光/反射和直射光，不要同时改多项后再猜原因。
C. 低优先且仅条件适用：SampleScene/未来开启后处理的相机，会得到质量级 SampleSceneProfile 的 Neutral、Bloom、Vignette。正式 PlayerCamera 当前 PP=0，因此不应直接全局改 Profile 声称修好正式游戏灰感。
D. 当前磁盘证据反对：全局雾（全关）、全局负饱和/低对比 ColorAdjustments（未发现）、正式相机 Bloom 灰幕（PP关）。
E. 未覆盖：Editor Scene View 与 Game 的显示差异、实际运行中的 Volume stack/环境探针缓存、显示器/HDR 输出、相机后处理临时覆盖。没有运行证据，不作根因结论。

五、最小实施方案（供 root 操作，不是本审计已执行）
1. 对 12 个 Assets/Scenes 场景只设置 RenderSettings.skybox 为同一个 ShelterNightSkybox。已是夜空的 Shelter 保持引用。优先通过 Unity 保存 RenderSettings，保留最新用户编辑和已有对象/灯光/布局。
2. 世界相机若是 SolidColor，改为 Skybox；已是 Skybox 的共享 PlayerCamera 不重复改动。只改 clearFlags/必要 fallbackColor，不改 transform、FOV、Cinemachine、UI Camera 或堆叠。Bootstrap 加载相机可保留暗色清屏，只要该场景 RenderSettings 同样持有夜空；若验收要求它也显示夜空，只改该相机 clearFlags，不触碰入口展示启用逻辑。
3. 首次完成背景后，拍同场景/机位的真实 Game 前后帧，尤其 Shelter 和 Ruins。若灰感仍在，再分别对照天空曝光、ambient/reflection 强度和主光，不先改变工程 Linear/HDR，也不为去灰强行打开所有相机 PP。现有夜空材质参数并非“发灰修复已验证”的证据。
4. 增加一个小型 Editor 默认环境帮助类，集中引用夜空材质，给新建场景赋值。订阅 EditorSceneManager.newSceneCreated；处理新增场景时临时切 active scene 再设置 RenderSettings，finally 恢复原 active scene，避免 Additive 新场景误改旧场景。排除 Play、Preview/Prefab 隔离场景；不在每次 Update/OpenScene 强制刷值或自动保存，保留显式编辑的空间。
5. 只靠 newSceneCreated 是否覆盖 Unity 6 的每种 Scene Template 路径，需要本机验证；本审计没有找到该事件的本地源码证据。项目内没有自定义模板，包内现成 URPBasicScenePipeline 实现了 ISceneTemplatePipeline.AfterTemplateInstantiation，可作为项目夜空模板的具体落点。若同时要求“任意模板新建也默认黑夜”，root 应验证 Ctrl+N / Empty / Basic(URP) 三条路径，并按实际事件顺序补模板创建完成回调，不能只验 Empty 就宣称全部生效。不要修改 Library/PackageCache。
6. 现有 Builder 需接入同一默认函数，或者至少在填充完成、保存之前显式 Apply。仅 creation callback 太早时，后续 Builder 可覆盖初始值：
   PlayerTestSceneBuilder.cs:81 生成共享玩家相机时仍写 SolidColor；:152 写 ambientLight；当前已有场景有存在保护，所以这不是每次启动都会覆盖。
   MinimumLoopSceneBuilder.cs:294 加载相机写 SolidColor；:363 写 ambientLight；CreateScene:493 NewScene(Empty,Additive)，fill 后立即 SaveScene。
   WarehouseTestSceneBuilder.cs:271、LocalizationTestSceneBuilder.cs:127 生成 SolidColor 世界相机。
   Backpack/Loot/Enemy/Player builders 写 ambientLight=(.5,.55,.65)。若后续采用明确夜间 AmbientMode/颜色策略，应改调用顺序，免得生成后又恢复白盒环境；无需为本任务重建正式场景。

建议最小验收
- 保存后重载 Shelter、Ruins；真实 Game 截图尺寸1920x1080，背景为夜间，玩家/无人机锥体/UI仍清楚，Cinemachine机位和控制未改变。
- 12 个场景逐一核对 RenderSettings.skybox 引用；世界相机 ClearFlags与Bootstrap加载相机例外有明确记录。
- 分别新建 Empty 与 Basic(URP)，保存重开仍绑定同一夜空；新建后旧 Additive 场景未被意外改脏。
- 若动了环境亮度或 Profile，保存前后固定机位对照；仅截图变暗不足以说明“灰感根因已查明”。
