一、数据由谁保存

01的ItemManager保存唯一一份ItemInstance：实例ID、当前归属、containerId、次数、保有状态和找回记录。
04的BackpackManager只保存BackpackGrid布局，每条BackpackPlacement引用既有ItemInstance，并保存X、Y、Rotated。不会复制HP、EV、次数或归属，不会为移动创建新身份。
BackpackPlacement没有可写属性；GetPlacements返回只读集合快照。移动替换一条记录，旧快照里的坐标不会随之改变。快照中的Item仍然是01的同一份权威实例，读取其Owner/UsesThisRound会得到最新状态。
BackpackManager挂在既有GameBootstrap的场景实例下，常驻由父入口提供。04没有第二个Singleton根、DontDestroyOnLoad调用、背包存档或新轮次流程。

四、坐标、占格与缩放

左上角为(0,0)，X向右，Y向下。Placement的X/Y总是物品矩形左上角，不是世界坐标。
原宽高读取ItemDataSO.width/height；Rotated=true代表90度，宽高交换，不改SO原尺寸。canRotate=false时任何旋转摆放均拒绝。
BackpackGrid使用简单List与矩形相交检查。先确认完整矩形在范围内，再比较其他物品，不能只用总空面积判断。坐标边界使用减法和必要的long比较，极大输入不会通过int溢出绕过边界。
CanPlace/CanMove只查询；TryAdd/TryMove先检查成功再修改。失败保持所有记录不变。同一实例不能重复添加；包内移动只忽略自己的原占格，仍检查其他物品。
BackpackView.TryScreenToCell通过RectTransformUtility.ScreenPointToLocalPointInRectangle转换，使用gridRoot.rect边缘、padding、cellSize和gap计算。边距与格子缝隙不作为有效目标格；CanvasScaler的缩放由RectTransform转换处理。面板须启用，存在EventSystem时还检查实际最上层射线命中属于本窗口，不能穿过来源面板或确认框放置。没有固定深度的ScreenToWorldPoint。
单个物品宽度为width*cellSize+(width-1)*gap；高度同理。物品左上角位置为padding+(x或y)*(cellSize+gap)。格子坐标不参与玩家X/Y/Z世界运动。
当前有效摆放目标仅为左侧真实gridRoot。右侧占位、中间世界区域及左侧详情区都不属于背包格子；拖到这些区域松手按面板外取消处理，不构成丢弃或向搜刮容器转移。

五、拖拽与取消为什么不会丢物

BeginItemDrag记录实例、原Placement、朝向以及按下位置所在的抓取格。真实布局和01归属完全不变；View只画半透明预览。合法位置显示绿色，非法位置红色，并显示当前语言原因。
每次拖拽使用一个递增token。UpdateDrag和EndDrag必须携带当前token；CancelDrag把有效token清零，所以受击后迟到的OnEndDrag或上一轮拖拽回调不能提交。ItemView停用时以自己的token调用CancelDrag(token)，不会误取消另一轮拖拽。
按R只改变预览的bool旋转与抓取偏移。松手时再次确认：当前拖拽仍有效，实例仍是01同一对象，Owner/ContainerId仍属于本包，原摆放未被其他操作更改，目标仍合法。随后TryMove再次完整校验并一次替换记录。
非法位置、格子缝隙或面板外松手只取消预览；不交换其他物品、不丢地、不删除任何身份。CancelDrag和Close重复调用安全。
Tab关闭、关闭按钮、有效伤害、死亡、控制器停用、换绑玩家、失去焦点/应用暂停都走统一取消路径。切语言只RefreshText，不清token、不改旋转、不重建正在拖拽的物品视图。

外部预览：BackpackUIController.BeginExternalPreview(instanceId)只接受现存World/Container/Storage实例且本包没有其Placement，记录原Owner/ContainerId后预览。取消不改来源、不调用TrySetOwner、不删除来源表现。EndDrag在有效token内先调用已绑定的ExternalDropRequested同步处理者；该回调未处理时，外部预览才取消并显示pending。04测试场景没有绑定06回调，因此只验证预览和取消，不能视为真实拾取已完成。真实来源和转移由06协调。

六、与02玩家协作

探索默认shelterContext=false；未准备、无玩家或死亡玩家不能打开。打开调用真实PlayerController.SetBackpackOpen(true)，由02禁止主动移动/跳跃/世界交互并保持当时站立或蹲伏。04不禁用PlayerController，不冻结刚体，不修改Time.timeScale，不替换Cinemachine。
正常关闭顺序：先设IsOpen=false → 原先打开时发布Closing清理来源会话 → CancelDrag并通知DragCancelled → 关闭View → SetBackpackOpen(false)。closing标记防止递归进入；Closing监听者只清理来源，不反向调用Close。只有存在拖拽时才发布DragCancelled。来源和预览均在解除玩家限制前结束。不使用CanAct阻止关闭，因为开包期间CanAct本来就是false。
只订阅PlayerHealth.NonLethalDamaged和Died。02接受有效伤害后，04同步取消并关闭；被无敌期拒绝的伤害不发NonLethalDamaged，因此不会误关包。死亡同样清理背包标记，但02的IsDead和死亡状态继续限制行动。
04不RecordLoss、不扣EV、不清全部携带物、不推进轮次。死亡时原布局完整保留，供08和06决定并执行实际损失/转移。
BindPlayer(newPlayer)先关闭并清理仍存在的旧玩家标记，再解除旧Health订阅，最后绑定新玩家。OnDisable同样清理；重新启用后重新解析常驻数据。
庇护所由08/09调用SetShelterContext(true)或在场景Inspector明确配置。该上下文允许未准备玩家或没有场景玩家时整理，但死亡玩家仍拒绝打开。没有有效存活且准备好的PlayerHealth时不能使用治疗物品。

七、物品使用只有一个入口

UI右键只由克隆的Player/UseItem回调处理；BackpackItemView.OnPointerClick只处理左键选择。回调通过EventSystem实际最上层命中的本包ItemView确定目标，避免点击其他UI时穿透使用。
BackpackUIController.TryUseHoveredItem要求开包、无拖拽且真实玩家有效存活，然后调用：
BackpackResult TryUseItem(string instanceId, PlayerHealth target, out ItemUseResult useResult)

BackpackResult表示04的布局与归属检查。只有其为Success后才读取useResult；useResult表示01的真实使用结果，或无有效PlayerHealth时的InvalidTarget。BackpackResult.Success本身不等于治疗成功。
管理器先确认真实实例、Owner==Backpack、ContainerId==本包、存在且合法的摆放，然后把同一个PlayerHealth作为IHealthTarget交给ItemManager.TryUseItem。
成功且Owner==Consumed时，先删对应实例的布局，再发Changed。成功且保留的医疗包原格不变。失败不改布局；满血不会扣次数、吃食物或腾格。
医疗包每轮一次、回满、食物回复1HP后消耗等规则全部由01现有配置与TryUseItem负责。04不BeginRound、不ResetForExploration、不修改IsRetained。
busy覆盖完整同步操作与Changed通知。治疗期间或监听者中重入移动、布局增删和使用会返回Busy，重复NotifyChanged不会递归。通知读取已经一致的数据，不承担第二次移除业务。

八、06可以调用的实际接口与顺序

BackpackManager.Resolve()：只在有效GameBootstrap.Instance下寻找启用的BackpackManager，避免新场景重复根延迟销毁期间绑定错实例。它不创建全局根。
bool Initialize(ItemManager source)：首次配置格子并记录真实来源；再次传同一来源返回true，布局不清空。换另一份ItemManager返回false。
ItemManager Items；int Width/Height；string ContainerId；bool IsReady。
IReadOnlyList<BackpackPlacement> GetPlacements()：布局只读快照。
bool TryGetPlacement(string instanceId, out BackpackPlacement placement)：查摆放。
BackpackResult TryGetCarriedItem(string instanceId, out ItemInstance item)：校验身份、归属、容器与合法摆放。
BackpackResult CanMove(string instanceId, int x, int y, bool rotated)：包内预览查询，无副作用。
BackpackResult TryMove(string instanceId, int x, int y, bool rotated)：包内提交，成功后发Changed。
BackpackResult CanPlaceExternal(string instanceId, int x, int y, bool rotated)：查询没有本包记录的现有活动实例。接受World/Container/Storage或本containerId的Backpack；拒绝重复、终止/待找回归属及其他背包containerId。
BackpackResult TryAddPlacement(string instanceId, int x, int y, bool rotated)：检查后新增一条布局，不改01归属、不发通知。
BackpackResult TryRemovePlacement(string instanceId, out BackpackPlacement removed)：只移除指定布局，返回原记录，不改01归属、不发通知。允许归属已转移或已由08记损后清理旧摆放。
BackpackResult TryRestorePlacement(BackpackPlacement placement)：用原实例与原位置/朝向重新检查后添加，不覆盖冲突记录，不自动恢复01归属、不发通知。失败返回原因，当前布局不变。
void NotifyChanged()；event Action Changed：完整协调操作结束后刷新显示。

06应先完成来源与目标的全部必要校验，再协调其来源布局、04布局与01.TrySetOwner。失败自行用保留的原Placement及来源状态恢复；04没有通用事务或跨容器协调器。只有来源、目标与01数据一致后才NotifyChanged，不能在半完成的布局加入后就刷新界面。
新增/恢复静默入口有意允许实例尚在来源归属，这只是提供同步协调所需的局部能力，不是拾取成功或所有权转移许可。终止状态Consumed/Lost/PendingRecovery不能借恢复布局复活。
BackpackResult实际值：Success、NotReady、InvalidConfiguration、NotFound、WrongOwner、WrongContainer、MissingPlacement、DuplicateInstance、RotationNotAllowed、OutOfBounds、Overlap、Busy。

06按用户授权补入的UI同步回调（04仍不引用06类型）：
- Func<bool> CanBeginDrag：来源状态可暂时阻止选择、开始拖拽与使用；未接时保持04原有行为。
- Action<int, Vector2, Camera> DragUpdated：04更新预览后通知唯一协调者当前token与指针，以便显示另一目标。
- Func<int, Vector2, Camera, bool> ExternalDropRequested：在有效token内同步处理松手；返回true表示已处理，04保存结果反馈并结束预览；返回false继续04原路径。不能把多个监听者串成业务提交链。
- event Action Closing、DragCancelled：清理来源会话和预览的生命周期通知，不执行第二次转移。
- int DragToken、Vector2Int DragGrabOffset、bool IsDragValid(int token)、void CancelDrag(int token)、void SetFeedback(string key)：用于验证当前拖拽、保留抓取格、取消指定预览和显示稳定反馈key。
06负责这些回调的绑定、解除与真实来源联合验收；04当前测试场景不绑定回调。它们是明确的单次同步接入点，不是通用事件总线或事务引擎。

九、03双语接入

BackpackText使用真实LocalizationTableSO.entries；每条LocalizationEntry包含key/chinese/english。普通背包键使用backpack.前缀；物品结果直接复用items.use.*。窄左栏使用backpack.language_hint显示简短F10提示，这只是一条显示文案；F10仍完全由03唯一监听，04没有第二个切语言入口。
物品名称与描述只从ItemDataSO.nameKey/descriptionKey查询；译文唯一编辑来源仍为ItemDataSO中英字段。背包表不复制物品译文。
动态文字调用LocalizationManager.GetText(key)、FormatText(key,args)，并配对订阅/解除LanguageChanged。BackpackUIController只保存FeedbackKey等稳定含义；切语言重查上一条反馈、选中物品和说明，也刷新右侧搜刮标题与未连接状态，不重新使用或移动。
BackpackView.Bind不因相同绑定而重建视图；LanguageChanged只RefreshText。关闭后新打开立即使用当前语言。全新运行默认中文由03负责，04没有F10监听。
静态测试HUD使用03的LocalizedText。04自己的测试场景把BackpackText接入LocalizationModule实例tables；09在正式场景按同样方式汇总实际使用的表。

十、08/09后续集成注意事项

布局在常驻BackpackModule中；UI、输入控制器、玩家和EventSystem属于场景。重载时旧UI取消预览并解除订阅，新UI调用ResolveBindings取得存活入口下的数据，不引用即将销毁的重复Bootstrap子模块。
成功撤离或普通换场景不清背包、不自动整理、不修改使用次数。08负责决定场景与玩家上下文；新玩家通过BindPlayer绑定，庇护所通过SetShelterContext设置。04不开新轮次、不结算EV或损失。
09复用BackpackUIController处理Tab/R/右键；不得另加第二个相同业务输入监听。F10仍由03独占。关闭UI对象时必须保留能够接收Tab的控制器。
仓库、箱子搜刮、地面拾取/丢放、撤离、死亡损失和正式场景转换均需与05/06/08/09联合验收；当前04测试上下文不能代替这些流程。
双侧布局只改变场景UI的展示与接线，不改变常驻BackpackModule的职责、物品身份、布局数据或保存时机。06后续应在右侧接入真实来源并协调转移；09继续保留中间世界视野及左侧背包既有输入入口。

复验建议按以下顺序进行并分别记录结果：
1. 站立开包，A/D与Space不能主动移动/跳跃，世界计时和运动方块继续；关闭后恢复正常控制。再按C蹲伏开包，松C仍保持打开时姿态。

3. 拖拽中按H，在有效伤害时立即关闭；再松鼠标不能迟到提交。等无敌结束后再打开，拖拽中K致命伤害应关闭且角色仍死亡，携带物仍完整等待08。
4. 满血右键医疗包/食物都拒绝。H受伤后使用食物，仅对应实例消耗且腾格；医疗包成功后保留，同轮再次受伤使用应提示额度已用。
5. V启动外部预览，再Escape/Tab取消；01实例仍在World且containerId未变。此项只验预览，不验真实转移。
6. F10中英来回切换，包括正在拖拽、关包重开和上一条错误反馈；无来源时右侧保持隐藏，ID、坐标、旋转、次数不变。检查中文无方框，左侧格子下的详情、英文和多行说明可读。
7. 在1280×720与800×600实际Game窗口尺寸重复点击、抓取非左上角、旋转和放置，确认预览与真实占格一致，左右面板不遮住中间世界，左侧下方详情与操作说明未被裁切。已完成这两尺寸的排队InputSystem→UGUI自动验证和截图检查；直接设置画面状态、自动输入与原生键鼠/人工验收分别记录，不混为同一种证据。
8. 同次运行重载BackpackTest，已提交摆放、ID、医疗包次数与语言保留，临时预览消失，食物不补发。

十二、答辩说明

“01保存这件物品是谁、属于哪里、用了几次；04保存它在背包哪几格。拖拽先显示预览，合法松手才改位置，受击只需取消预览，因此不会丢物。UI读取这些数据并显示03提供的当前语言文字。”

具体看代码：BackpackGrid.CanMove不写数据，TryMove检查后替换一条Placement；UIController.CancelDrag只清临时token与预览；Manager.TryUseItem先让01完成真实使用，再删除已消耗实例的占格，最后通知View。这里的正确性来自明确顺序和数据只有一份，不需要通用事务框架。

十四、04A Ctrl快捷转移入口（代码就绪，运行待07）

BackpackUIController新增public Func<string, bool> QuickTransferRequested { get; set; }与public bool TryQuickTransfer(string instanceId)。06绑定同步回调，负责唯一有效目标选择、真实提交及双侧反馈；04没有目标查找、Items/Transfers或Loot反向依赖。未绑定返回false。卸载由06只移除自己绑定的回调，04关包只作手势失效，不随意清除桥接委托。
入口验证本地组件/背包已打开、权威物品仍归本包且摆放合法、无拖拽、玩家状态与场景切换锁；庇护所仍允许未准备或无玩家。复用CanBeginDrag处理真实丢弃确认和对侧拖拽限制。同步请求期间禁止递归快捷请求、普通拖拽与使用；闸门回调后的状态再次检查。返回最终回调结果，false不覆盖06反馈，不自动丢弃。
BackpackItemView通过UGUI PointerDown读取Input System左右Ctrl，只在有效PointerUp→PointerClick发一次快捷请求。按住不逐帧调用；本次按压成功或失败都不启动普通拖拽/选择。快捷按压移动超过拖拽阈值只取消，不在松手时补发快捷请求。普通按下后再按Ctrl仍走普通路径。使用入口同时检查快捷按压以及同帧Ctrl+左右键，避免UseItem先于UGUI回调使用物品。没有注册新的轮询或InputAction。
关闭、禁用或换绑清按压状态；关闭使InputSession失效，旧Click/BeginDrag不能借用重开的面板。相同实例的Bind刷新保留手势，F10不重新提交。受击和死亡沿用原有Close入口，场景切换锁也禁止重开。

BackpackManager新增public BackpackResult TryFindSpaceForExternal(string instanceId, bool preferredRotated, out Vector2Int cell, out bool rotated)。

成功返回Success和合法cell/rotated。失败cell=(-1,-1)，rotated保持preferredRotated；已有身份/初始化/忙/重复错误原样返回。禁止旋转却传true返回RotationNotAllowed；至少有能容纳尺寸的位置但全部占用返回Overlap；全部允许方向都超大返回OutOfBounds。查询不是来源许可或最终提交，06仍须完整复验。
