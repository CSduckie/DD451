一、当前里程碑

先交付可反复游玩的最小循环：
启动进入庇护所 → 整理背包/仓库 → 出发 → 废墟搜索与拾取 → 另一端互动撤离 → 即时结算回庇护所 → 自由存取 → 再次出发。

敌人AI与完整死亡风险后置，已确认的最终P0规则保留。此阶段地图不布置敌人或主动伤害源，不全局关闭真实生命、死亡限制或04受击取消逻辑。
00—06编号及已有实现保留；06继续当前转移与搜刮范围，不要求返工。新07统一承担必要流程与场景整合，避免两个聊天互等。

二、新任务顺序

06 物品转移与搜刮（继续）
依赖：01—05实际接口与资源。
交付：背包/仓库双向转移、地面拾放、可配置箱子、独立概率、逐件搜索、中断恢复和03双语。
验收：真实指针操作可用，失败不丢物/不复制；同轮不重抽；已揭示保留、当前搜索项重计。
边界：不承担正式场景与完整流程，提供给新07可接入的轮次、来源和转移入口。

07 最小循环整合（下一项）
依赖：00—06真实模块；04/05最新布局验收与06真实跨容器操作须核对。可先做不依赖06完成的白盒与基础流程，最终交付必须接真实06。
交付：同一任务完成常驻模块接线、正式入口、庇护所白盒、废墟白盒、出发/撤离、结算、轮次和来源收尾。
里程碑：从正式入口开始，无调试按钮、无手动换场景，连续完成至少两轮“出发—搜刮—撤离—整理”。
不另造物品、容器、语言、输入或角色系统；简单流程枚举、明确方法与必要场景加载即可。

08 最小循环验收与修复
依赖：新07已有流程源码及真实00—06模块。07当前交接仍为源码阶段；08开工核对最新状态，允许执行已有场景搭建器、补齐正式接线后再验收，不另造第二套流程。
交付：针对同一套正式场景进行功能回归、键鼠操作与双语检查，修复实际阻断问题，给出Windows键鼠试玩构建。
验收：连续三轮不丢物/不复制；一次撤离只结算一次；满仓仍能返回和再出发；首次升级与运行中保留正确；无新增报错，打包后循环可用。
边界：不创建第二套场景或流程，不把敌人及死亡分支当作本阶段已验收。构建注明“无敌人最小循环版”，不是最终P0。

09 敌人AI与潜行（原07，后置）
依赖：新08最小循环稳定，以及02现有共用状态机。
交付：按用户ARPG状态机改用3D物理的无人机；Collider配置并显示视野；遮挡、追击、蹲伏掩体与接触自爆。
验收：代码控制状态和动画，无需手工连接Animator Transition；自爆本轮不重生，下轮刷新；实际检测与可视范围一致。
边界：先在模块场景验证，正式风险和死亡流程在新10整合；不为了敌人重做已稳定的经济、物品和场景切换。

10 风险流程整合与完整P0交付
依赖：新08可玩循环和新09敌人模块。
交付：在同一正式废墟中接入敌人，完成有效受击/搜索中断、死亡返回、全部携带物损失、EV更新及下轮原点找回，完成完整P0回归与Windows构建。
验收：成功撤离与死亡两条分支均正确；仓库物品安全，死亡携带物按规则损失；唯一物品保持身份并可找回；已有扩容不撤销；完整循环不回退。
边界：沿用精简实现，不新增磁盘存档、商店、声音诱饵、第二敌人类型或未经确认的玩法。

三、新07的具体范围

1. 正式入口与庇护所
- 使用已有GameBootstrap保存运行数据；场景中的玩家、摄像机和UI绑定存活模块。
- 一间简单3D白盒庇护所，放置玩家出生点、仓库交互入口与出发入口。
- 复用04背包、05仓库/EV/升级UI；真实背包与仓库经06转移，不借测试驱动伪造物品归属。
- 无需装饰、高精模型、建造系统或复杂主菜单。玩家可继续胶囊占位，摄像机继续Cinemachine。

2. 出发与废墟
- 从庇护所交互出发，加载一张可完成的3D横版白盒废墟。
- 玩家X左右、Y高度、Z固定；入口与撤离点在两端。
- 放置可配置箱子、地面物与清楚的撤离入口，不放敌人或主动伤害源。
- 至少一组100%示例掉落保证首次试玩有东西可搜；这只是场景配置，不改变06独立概率算法。
- 新一轮明确调用01轮次入口、02玩家准备及06来源准备，玩家恢复满血，医疗包新轮额度可用；切UI或普通重载不能推进轮次。

3. 搜刮与撤离
- 使用真实06逐件搜索/拾放和04背包，正常关闭仍保留已揭示物并重置未完成项。
- 撤离点交互立即撤离；无读条、无杀敌/清追击条件。
- 防止连续点击产生重复加载、重复结算或重复发物；失败应保留可恢复的数据状态，不用重置物品修复。
- 完成成功撤离的保有标记后统一刷新EV，背包摆放原样保留；不强制卸仓、清包或整理确认。
- 同时正确处理本轮未带回的地面/箱内记录；已保有物被留在外面时对应保有与EV应变化，唯一物品下轮在原点找回同一身份。
- 来源收尾在清旧数据前完成；场景卸载本身不等于记损，不能留下无法绑定的旧实例。

4. 返回、存取与再次出发
- 返回庇护所后背包仍保存带回物品，可自由转仓，也可继续留包。
- 满仓只影响能否合法转入，不能卡住撤离或下一轮出发。
- 仓库物品、摆放、尺寸、升级标记和本次选择的语言跨场景保留。
- 正确关闭旧界面、取消拖拽、解绑旧玩家；新场景只有一份有效输入与UI绑定。
- 本次运行的新轮刷新普通掉落，唯一物品按当前归属与原点规则处理。
- 每次全新运行默认中文；运行中F10切换后跨场景保持，不新增磁盘存档。

五、最低验收路线

启动 → 中文庇护所 → 打开真实背包/仓库 → 出发 → 搜索并拾取至少两件物品 → 中途关闭后重开验证搜索规则 → 物品放回箱子再取回 → 另一端交互撤离 → 背包原样保留且新物品计EV → 自由存入仓库/取回 → 带旧物再次出发 → 搜刮并返回。
新版08执行连续三轮：首轮带回娃娃与医疗包、入库和升级；第二轮两件带出，探索中娃娃确认丢弃、医疗包放回箱子后遗留撤离；第三轮原点找回同一身份并再次保有/存取。具体步骤和数据检查见08_Minimum_Loop_Validation.txt。
最新用户规则：普通背包物确认丢弃后销毁，唯一物下一轮原点恢复，不再测试主动丢地后同轮捡回。地图原生拾取物及箱子放回仍保留。仓库升级只向下增行，当前20×20→20×24示例，原物品不因升级缩放。

补验：F10跨场景保持；重复撤离输入不重复结算；满仓不阻塞；EV7手动免费升级后EV下降仍扩容；新轮普通掉落刷新；已保有唯一物不复制；外面遗留的唯一物下轮回原点；全新运行从配置初始状态开始。
上述只能在真实模块和正式场景中执行通过后标记完成，模块测试成绩与实际键鼠试玩分开记录。
