Implementation interpretation
Add independently authorable scene camera movement bounds using the installed CinemachineConfiner3D, without changing camera projection, FOV, offsets or player movement rules.
Use each gameplay scene's own CameraBounds GameObject with enabled BoxCollider, isTrigger=true, no renderer. Set its center/size in Inspector; do not parent it under the moving player/follow target.
Place volume around allowable CAMERA positions, including the existing camera Z offset (-12 in current setup); do not use a thin box around player Z0 or shrink camera distance unexpectedly.
Do not reuse interaction TriggerBox for camera bounds or add Interactable; camera bounds must not block movement, rays, ground tests or source/drop validation.
Use current native Cinemachine confining, no hand-coded LateUpdate clamp or new camera manager/framework.
Preserve current lens settings. Confiner3D controls position center; for 1920x1080 compose/tune the allowable center rectangle with view margins. Do not claim mathematically guaranteed full-screen edge confinement for arbitrary geometry/projections. If user later requests that behavior, make it explicit rather than silently switch to 2D physics or change lens.
Per-scene Inspector reference is authoritative, no global Find selecting another additive scene's bounds.
CameraBounds is a scene instance reference, not a cross-scene reference baked into the shared prefab.
No visible-player scenes/cameras need a dummy follow camera just to satisfy this request: Bootstrap remains the system/loading entry. All playable maps and actual player/camera module scenes need an independently configurable boundary. Future scene setup instructions must include this.

4. Center bounds include current camera Z; perspective/FOV/follow distance remain authored values, player Z unchanged.
5. Real Cinemachine/Brain output is verified, not only component presence or a direct test clamp.
6. Departure, extraction, second departure and within-run teleport switch/reset correctly, without old bounds pull-back or a first-frame jump to the other scene.

8. No solid collisions/raycast interference from CameraBounds; E TriggerBox, source sessions and item movement still work.
